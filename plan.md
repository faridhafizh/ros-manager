## Context

Bangun `mikrotik-fleet-automator` dari repo kosong sebagai aplikasi Python untuk mengelola beberapa router MikroTik. Cakupan mencakup seluruh MVP dan stretch: CLI Typer, inventaris YAML, health check dan backup konfigurasi, ringkasan terminal/JSON/CSV, pytest dengan koneksi mock, Telegram, diff backup, scheduler interval, dan FastAPI untuk memicu backup. Gunakan RouterOS API untuk pengukuran serta SSH untuk mengambil konfigurasi: dokumentasi MikroTik menyatakan `/export` hanya tersedia di CLI, bukan API.

## Approach

1. **Bangun paket dan konfigurasi inventaris.** Tambahkan `pyproject.toml` dengan paket `mikrotik-fleet-automator`, CLI entry point `mfa = mikrotik_fleet_automator.cli:app`, Python 3.11+, dan dependencies runtime `typer`, `PyYAML`, `librouteros`, `paramiko`, `fastapi`, `uvicorn`; gunakan pytest sebagai dependency development. Implementasikan `src/mikrotik_fleet_automator/config.py` dan `models.py`: `load_config(path) -> AppConfig` membaca YAML dengan bentuk top-level `backup_dir`, `routers`, dan opsional `telegram`, `routers` wajib non-kosong; setiap router memiliki `name`, `host`, `username`, `password_env`, `api_port` (default 8729), `api_tls` (default `true`), `api_ca_file` (opsional), `ssh_port` (default 22), dan `ssh_known_hosts` (default `~/.ssh/known_hosts`). Ambil password hanya dari environment variable bernama `password_env`; jika tidak ada, duplikasi nama router, nilai wajib kosong, YAML rusak, atau nilai/tipe tidak valid, tampilkan error konfigurasi yang menunjuk field/router dan hentikan command sebelum koneksi. `backup_dir` default `backups` relatif ke working directory. Jangan pernah menaruh password langsung di YAML atau log.

2. **Implementasikan adapter koneksi MikroTik yang mudah dimock.** Tambahkan `router.py` dengan `RouterClient`/factory internal yang menutup koneksi pada semua jalur keluar. Buat koneksi API dengan `librouteros.connect(username=..., password=..., host=..., port=..., ssl_wrapper=...)`; untuk TLS buat `ssl.create_default_context(cafile=api_ca_file)` dan gunakan context tervalidasi, tanpa menonaktifkan verifikasi sertifikat. Bila `api_tls: false`, koneksi plain hanya jika dinyatakan eksplisit dan gunakan default port 8728 bila `api_port` tidak ditulis. Implementasikan `get_health() -> RouterHealth` menggunakan `/system/resource/print` untuk `cpu-load`, `total-memory`, `free-memory`; `/system/health/print` untuk sensor temperatur yang tersedia; `/interface/print` untuk nama, tipe, `running`, dan `disabled`. Sensor temperatur dapat tidak tersedia dan menjadi `null`, bukan kegagalan check; normalisasikan representasi temperatur RouterOS yang dapat dibaca menjadi Celsius. Implementasikan `export_config() -> str` menggunakan Paramiko: load host keys dari `ssh_known_hosts`, `RejectPolicy` untuk host key tak dikenal/tidak cocok, autentikasi username plus password dari `password_env`, lalu jalankan `/export terse` dan kembalikan stdout UTF-8. Kegagalan koneksi/perintah per-router harus menjadi error yang bisa ditampilkan per-router; jangan mengembalikan backup kosong sebagai sukses. Ekspor default RouterOS menyembunyikan informasi sensitif; jangan meminta `show-sensitive`.

3. **Selesaikan alur service, backup, dan ringkasan MVP.** Tambahkan `service.py` untuk menjalankan health check dan/atau backup pada tiap router, mengisolasi kegagalan per-router sehingga hasil router lain tetap dikumpulkan. Tambahkan `storage.py`: tulis ekspor ke `{backup_dir}/{router_name}_{UTC timestamp}.rsc`, timestamp format `YYYYMMDDTHHMMSS.ffffffZ`; buat direktori jika belum ada dan tulis atomik agar proses terputus tidak meninggalkan file backup parsial. Definisikan hasil check JSON sebagai objek `{"generated_at": "ISO-8601 UTC", "routers": [{"name": str, "host": str, "status": "ok"|"error", "error": str|null, "temperature_c": number|null, "cpu_load_percent": number|null, "memory_total_bytes": int|null, "memory_free_bytes": int|null, "interfaces": [{"name": str, "type": str|null, "running": bool|null, "disabled": bool|null}]}]}`. Terminal menampilkan satu baris per router dengan status dan ringkasan metrik, lalu error ringkas jika gagal. JSON menulis skema di atas; CSV menulis satu baris/router dengan kolom tetap `name,host,status,temperature_c,cpu_load_percent,memory_total_bytes,memory_free_bytes,interfaces_up,interfaces_total,error`; nilai sensor hilang dan jumlah interface yang tak dapat ditentukan ditulis kosong. Kegagalan router membuat exit code non-zero setelah seluruh inventaris diproses. Tambahkan command Typer `mfa check --config PATH --format text|json|csv --output PATH_OPTIONAL`, `mfa backup --config PATH`, dan `mfa run --config PATH --format text|json|csv --output PATH_OPTIONAL`; `run` menjalankan check serta backup untuk tiap router dan merangkum keduanya. Output berkas menggunakan encoding UTF-8; output terminal tetap tersedia bila `--output` tidak diberikan.

4. **Tambahkan diff, notifikasi Telegram, dan scheduler.** Tambahkan `mfa diff --old PATH --new PATH` untuk mencetak unified diff teks backup `.rsc`; keluar dengan 0 jika sama dan 1 jika berbeda, error/exit non-zero selain 1 jika file tidak dapat dibaca. Tambahkan konfigurasi opsional `telegram.token_env` dan `telegram.chat_id`; kirim ringkasan `run` setelah semua router selesai dengan HTTPS Telegram Bot API dan token dari environment, tanpa mencetak token. Jika blok Telegram tidak ada, notifikasi nonaktif; jika salah satu dari dua field ada tanpa yang lain atau token env tidak tersedia, command yang meminta notifikasi melaporkan error, tanpa menyamarkannya sebagai sukses. Tambahkan `mfa schedule --config PATH --interval-seconds N` yang menjalankan `run` segera lalu berulang dengan interval detik positif sampai dihentikan pengguna; teruskan ringkasan setiap siklus dan jangan mulai siklus overlap.

5. **Tambahkan endpoint FastAPI dan pengujian terintegrasi.** Tambahkan `api.py` dengan `create_app(config_path: Path) -> FastAPI` dan `POST /backups`, yang menjalankan backup seluruh inventaris melalui service yang sama dan mengembalikan hasil per-router JSON (HTTP 200 walaupun sebagian router gagal, dengan status error per router); kegagalan membaca/validasi konfigurasi menghasilkan HTTP 500 dengan pesan aman tanpa rahasia. Tambahkan `mfa serve --config PATH --host 127.0.0.1 --port 8000` untuk menjalankan Uvicorn. Letakkan test di `tests/` dan injeksikan/mock adapter API, SSH, filesystem, dan pemanggil Telegram; uji parsing konfigurasi valid/tidak valid dan env password hilang; pemetaan metrik dan temperatur opsional; status interface; backup bertimestamp/atomik dan kegagalan SSH; agregasi parsial serta kode keluar CLI; JSON/CSV kolom dan nilai hilang; diff identik/berbeda; Telegram tidak aktif, sukses, dan konfigurasi/token invalid; scheduler run awal, interval, dan stop; endpoint sukses/parsial/config invalid. Jangan butuh router fisik, jaringan Internet, atau token Telegram dalam suite.

## Critical files & anchors

- `pyproject.toml` — metadata paket, dependency groups, dan entry point executable.
- `src/mikrotik_fleet_automator/config.py` — validasi schema YAML dan pembacaan secret environment, pola yang dipakai semua command.
- `src/mikrotik_fleet_automator/router.py` — batas adapter API/SSH; dokumentasi `/export` CLI-only membuat pemisahan koneksi diperlukan.
- `src/mikrotik_fleet_automator/service.py` — alur per-router, isolasi error, dan kontrak hasil bersama CLI/API/scheduler.
- `src/mikrotik_fleet_automator/cli.py` — command Typer, opsi, format output, serta pemetaan exit code.

## Verification

- Jalankan dari root repo: `python -m pip install -e '.[dev]'`, lalu `pytest`. Suite menggunakan mock, tidak menyentuh router sungguhan.
- Jalankan smoke CLI lokal: buat inventaris YAML sementara dengan dua router mock pada test, satu sukses dan satu gagal; pastikan `check --format json` menghasilkan dua entri, error pada router kedua, sensor temperatur kosong bila tidak tersedia, dan exit code non-zero. Pastikan format CSV memiliki header kolom tetap serta satu baris per router.
- Uji backup service terhadap adapter SSH mock yang mengembalikan `/system identity\n`; hasil harus berupa satu file `.rsc` dengan timestamp UTC sesuai format dan isi tepat, lalu mock kegagalan SSH harus tidak menghasilkan file sukses.
- Uji `diff` dengan dua file backup identik (exit 0, tanpa hunks) dan dua file berbeda (unified diff tercetak, exit 1).
- Uji `POST /backups` via FastAPI `TestClient`: inventaris sukses/parsial menghasilkan HTTP 200 dan status per-router yang sesuai; YAML invalid menghasilkan HTTP 500 tanpa password/token pada respons.
- Uji Telegram dan scheduler tanpa jaringan/waktu nyata: mock HTTPS request dan fungsi tunggu/clock; verifikasi token tidak muncul pada log/hasil, scheduler memulai run pertama segera dan berhenti ketika sinyal stop diterima.
- Verifikasi dengan `mfa --help` dan `mfa check --help` bahwa entry point dan opsi command tersedia.

## Assumptions & contingencies

- Pilihan tetap: MVP plus seluruh fitur stretch; CLI Typer; RouterOS API untuk health check dan SSH untuk backup konfigurasi lengkap; password dibaca dari environment variable, bukan file inventaris.
- TLS API dan validasi host key SSH aktif secara default. Untuk RouterOS API-SSL dengan CA privat, pengguna mengisi `api_ca_file`; jika sertifikat tidak dapat divalidasi, koneksi gagal aman dan tidak beralih ke plaintext. Pengguna yang sengaja memakai API plaintext harus menetapkan `api_tls: false` eksplisit.
- Nilai temperatur bergantung model/router; ketidaktersediaan sensor adalah data opsional dan tidak menggagalkan health check.
- `export` RouterOS tidak mencakup semua rahasia atau artefak (termasuk password user dan sertifikat terpasang); file `.rsc` adalah export konfigurasi teks, bukan clone biner penuh. Jangan mengklaimnya sebagai backup biner penuh.
